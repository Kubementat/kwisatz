# v2.0.0

Released 2026-11-24. 33 commits since `v1.2.0`, on `develop`, merged to `main` for this tag.
98 files changed, +6 215 / −1 691.

## What this release is

**kwisatz installs as a wheel, and the repo trims its scope.** You can now `uvx kwisatz` or
`uv tool install kwisatz` — no checkout — and the tool keeps *your* files in `~/.config/kwisatz/`
and its own state in `~/.local/state/kwisatz/`, while the bundled payload stays read-only. Two
new services (`setup-comfyui`, `setup-pi-pocket`) join the catalogue. And six host/desktop
recipes moved out to the sibling repository **kwisatz-extras**, which is why this tag is 2.0.0
and not 1.3.0.

| Area | Change |
|---|---|
| Distribution | `uvx kwisatz` / `uv tool install kwisatz`; read-only payload bundled in the wheel |
| Layout | payload / config / state split: `$KWISATZ_HOME` (`~/.config/kwisatz/`) and `~/.local/state/kwisatz/` |
| New services | `setup-comfyui`, `setup-pi-pocket` |
| New tooling | `kwisatz versions`, sparse per-machine `versions.yml` override, `init --import`, `--mode uvx/tool` in the VM suite |
| Breaking | six `tasks/` scripts and their config keys and pins moved to **kwisatz-extras** |
| Notable fixes | vLLM `.env` comment stripping, Postiz cold-start registration retry, llama.cpp clone ownership, VM-sweep failure classes |

## New: installed mode — `uvx kwisatz`, no checkout

The wheel bundles everything the tasks need as a **read-only payload**, and the CLI separates
it from what belongs to the user and to the machine:

| Kind | Lives in | Written by |
|---|---|---|
| Payload (tasks, templates, `lib/`, bundled `versions.yml`) | inside the wheel / unpacked payload dir | only releases |
| User files: `machine-config.yml`, `models.yml`, `gateway.yml`, a sparse `versions.yml` | `~/.config/kwisatz/` (`$KWISATZ_HOME`) | you, or `kwisatz init` |
| State: applied-task state, task logs | `~/.local/state/kwisatz/` | the orchestrator |

```bash
uvx kwisatz status              # one-off, nothing installed
uv tool install kwisatz         # persistent CLI
kwisatz init --import ~/kwisatz # seed the config dir from an existing checkout
```

Tasks running from the payload read their config through `kw_config_file`, so `models.yml` and
`gateway.yml` resolve to the config dir, never to the wheel. A re-run converges exactly as it
did from a checkout; installed mode runs task scripts from the state dir, not the payload.
A machine-wide lock keeps two `apply` runs on the same box from stepping on each other.

From the repo, everything keeps working unchanged: `./kwisatz apply …` still deploys the
working tree.

## New: per-machine version overrides — `kwisatz versions`

The bundled `versions.yml` is the default for every pin. A sparse file at
`~/.config/kwisatz/versions.yml` holds only the pins *you* changed — per component, per field —
and wins over the bundle. Your usual overrides (script argument, `FORGEJO_IMAGE`-style
variables, `env:` in the config, `apply --env`) still win over both, in the same order as before.

```bash
kwisatz versions             # effective pins, and where each comes from
kwisatz versions --json      # the same for machines
```

## New service: `setup-comfyui`

ComfyUI on a DGX Spark, either as its own `comfyui.service` or behind llama-swap as the
`comfyui_auto` model (started through `http://<host>:9292/comfyui/` once `setup-llama-swap`
has run). An MCP server is wired in. ComfyUI has no authentication, so the default bind is
loopback, and it stays off unless you start it — next to a loaded LLM it can exhaust unified
memory.

```yaml
  setup-comfyui:
    enabled: false
    env:
      COMFYUI_SUPERVISOR: systemd   # or: llama-swap
      COMFYUI_PORT: '8188'
      COMFYUI_LISTEN: 127.0.0.1
      COMFYUI_AUTOSTART: 'false'
```

## New service: `setup-pi-pocket`

Pi Pocket — the web app for the `pi` agent — in Docker, built from the tag pinned in
`versions.yml`. Optional opt-ins: sharing your host `~/.pi` sign-ins, extra project binds,
Traefik under your domain.

```yaml
  setup-pi-pocket:
    enabled: false
    env:
      # PI_POCKET_PORT: "8787"
      # PI_POCKET_TRAEFIK: "true"
      # PI_POCKET_PI_DIR: /srv/pi-pocket/data/pi   # set to $HOME/.pi to share sign-ins
    args: []
```

## Changed: `setup-colqwen` publishes on its own bind variable

ColQwen now honours `COLQWEN_BIND`, defaulting to loopback — it used to publish more broadly
than it needed to. Set it only to expose the service to your LAN.

## Breaking: six recipes moved to kwisatz-extras

These were host/desktop or agent recipes, not server services, and they outgrew this repo.
They, their templates, their config keys and their `versions.yml` pins now live in the sibling
repository **kwisatz-extras**:

- `tasks/setup-brave.sh`, `setup-lm-studio.sh`, `setup-nanobot.sh`, `setup-neovim.sh`,
  `setup-whispering.sh`, `setup-zed.sh`
- `templates/nanobot`, `templates/neovim`, `templates/whispering`
- config keys and pins: `setup-brave`, `lm-studio`, `nanobot`, `neovim`, `whispering`, `zed`

Nothing in kwisatz references a removed task any more — the config-lint guard that checks every
example-config key names a real entrypoint is green. If you relied on one of these six, install
kwisatz-extras and run it from there; everything you already deployed keeps running, but a
re-run of `kwisatz apply` will no longer converge them.

## Fixed

- **`setup-vllm`** — re-runs strip inline comments from values read back out of `.env`, so a
  commented-out line no longer poisons the reused value.
- **`setup-postiz`** — the first-time registration retries while a cold stack answers 502,
  instead of dying at startup.
- **`setup-postiz`** — the temporal-ui healthcheck no longer needs `curl` inside the image.
- **`setup-llama-cpp`** — clones `/opt/llama.cpp` privileged, then drops ownership; resolves git
  config outside the invoking repo, so it no longer depends on where it was run from.
- **`setup-agent-docker-runner` / `setup-concourse`** — `adr` is verified in `~/.local/bin` and
  the PATH is patched in `bashrc`; the worker loads `ip_tables`.
- **VM-sweep fixes** — the failure classes found by the 2026-11-11 full sweep are repaired,
  including the `setup-pi-pocket` review round (`.env` reuse of layout keys, newest login link,
  `src` ownership, bind validation, the shown compose command).
- **Versions hygiene** — every non-HELD pin bumped to latest (2026-11-11 and 2026-11-23), and
  llama-cpp made trackable by `check-versions`.

## Config file

Breaking in the narrow sense: the six config keys listed above are **gone**. If your
`machine-config.yml` still sets them, `kwisatz apply` no longer errors — those keys simply name
no entrypoint — but you should delete them and manage those six hosts from kwisatz-extras.
Everything else is additive: `setup-comfyui` and `setup-pi-pocket` ship disabled, and the
config-dir/state-dir layout needs no config change.

## Upgrade notes

1. From a checkout: `git pull && kwisatz status` — nothing new runs by itself.
2. To try the wheel: `uvx kwisatz status`. To make it stick: `uv tool install kwisatz`, then
   `kwisatz init --import <your-checkout>` to seed `~/.config/kwisatz/`.
3. Remove the six removed service blocks from your `machine-config.yml` (see the Breaking
   section) — the rest of the file is untouched.
4. A re-run of any remaining task converges and refreshes its pins from `versions.yml`; data is
   preserved.
