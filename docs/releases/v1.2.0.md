## What this release is

**Two new services and a version-pinning spine.** Everything kwisatz installs now reads its
upstream version from one file, `versions.yml`, so a bump is a one-line PR instead of a grep
across 66 task scripts — and Renovate opens those PRs for you. Alongside that: self-hosted
Matrix team chat, and a private LiteLLM gateway that puts one endpoint in front of several
llama-swap boxes.

| Area | Change |
|---|---|
| New services | `setup-matrix`, `setup-renovate`, `setup-llm-gateway` |
| New tooling | `versions.yml` + `kw_*` helpers, `renovate.json`, `utilities/check-versions.sh`, a Concourse job that runs the Renovate lookup |
| Notable fixes | Forgejo 15 LTS, fail2ban jail, Concourse worker name, OpenWebUI re-run port, `ORCA_VERSION` env leak, `check-versions --json` |
| Breaking | Nothing. Three new `enabled: false` config entries; every old script keeps its variables |

## New service: `setup-matrix`

Self-hosted Matrix team chat behind the shared Traefik proxy: Synapse + PostgreSQL 17 + Matrix
Authentication Service (MAS) + Element Web + `.well-known` delegation. Optional voice/video
calls (LiveKit + `lk-jwt-service`), the Ketesa admin UI, federation, and Prometheus metrics.
All config is rendered from `templates/matrix/` — nothing is generated inline.

First run creates the MAS admin and the signing keys; every re-run reuses them, so secrets are
never rotated against a persisted volume.

```yaml
  setup-matrix:
    enabled: false
    description: Install Matrix team chat (Synapse + MAS + Element Web, optional calls) behind Traefik
    # MATRIX_SERVER_NAME is REQUIRED and can never change afterwards (it is the
    # part after the colon in @alice:example.com) — the script refuses to continue
    # if the value differs from the one in an existing /srv/matrix/.env.
    env:
      MATRIX_SERVER_NAME: example.com
      # MATRIX_RTC: 'true'          # voice/video calls (LiveKit, 7881/tcp + 7882/udp)
      # MATRIX_FEDERATION: 'true'   # talk to other Matrix servers (default: private)
    args: []
```

Ports, domains, and the admin bootstrap are documented in [`README_MATRIX.md`](../../README_MATRIX.md).

## New service: `setup-renovate`

Self-hosted Renovate on a systemd timer against Forgejo. It reads each repository's
`renovate.json`, keeps the Dependency Dashboard current, and opens bump PRs — nothing is
merged automatically. Runs as a service, not a container, so it leaves no stack behind.

```yaml
  setup-renovate:
    enabled: false
    description: Self-hosted Renovate on a timer — bump PRs for versions.yml on Forgejo
    env:
      RENOVATE_ENDPOINT: https://git.example.com/api/v1   # required on first run
      RENOVATE_REPOSITORIES: denkfabrik/kwisatz
      # RENOVATE_SCHEDULE: daily          # systemd OnCalendar
      # Tokens go in once: kwisatz apply renovate --env RENOVATE_TOKEN=...
      # they land in /srv/renovate/.env (mode 600) and are read back, never rotated.
    args: []
```

## New service: `setup-llm-gateway`

One private, OpenAI- and Anthropic-compatible endpoint in front of the llama-swap boxes.
LiteLLM picks the box that serves each request, pins every turn of a session to the box that
served turn 1 (so the prefix cache is reused), honours hard per-deployment capacity caps, and
fails over to a peer.

Nothing is published to the public net, and — because Docker's published ports bypass `ufw` —
the source allow-list is enforced in the `DOCKER-USER` iptables chain by a tagged
`llm-gateway-firewall.service`, not by `ufw`.

```yaml
  setup-llm-gateway:
    enabled: false
    description: Private LiteLLM gateway in front of the llama-swap boxes
    env:
      LLM_GATEWAY_DIR: /srv/llm-gateway
    args: []
```

Routing lives in `gateway.yml`, and the wiring (endpoints, agent config, break-glass path) is
in [`README_LLM_GATEWAY.md`](../../README_LLM_GATEWAY.md).

## Changed: central version pins (`versions.yml`)

Every upstream version kwisatz installs — 69 pins across images, GitHub releases/tags, PyPI,
and git refs — moved out of the task scripts and into
[`versions.yml`](../../versions.yml), read through three helpers in `lib/helpers.sh`:

| Helper | Prints |
|---|---|
| `kw_image <key>` | `package:version[@digest]` |
| `kw_version <key>` | the `version` field |
| `kw_pin <key> [field]` | one field of an entry (`version`, `package`, `datasource`, `digest`) |

Every existing override still wins, in the usual precedence order: script argument, `*_IMAGE`
/ `*_VERSION` environment variable, `env:` in `machine-config.yml`, `kwisatz apply --env` —
and the pin last. So `OPENWEBUI_IMAGE=ghcr.io/…:<tag> ./tasks/setup-openwebui.sh` behaves
exactly as before.

Pins whose next **major** breaks persisted data carry a `# HELD <reason>` comment on the entry
*and* an `allowedVersions` rule in `renovate.json`; `tests/unit/test_versions.py` asserts the
two never drift, which is why `setup-postiz` keeps its postgres and elasticsearch majors.
`setup-forgejo` likewise moved to the 15 LTS line and is held there.

- ~35 task scripts refactored to read their pins from `versions.yml`; `setup-basics` installs
  `python3-yaml` before the first script that needs it.
- `utilities/check-versions.sh` prints what is outdated without opening anything
  (`--json` for machines).
- Two guards: a schema/usage/lint guard over `versions.yml`, and a test that fails if any task
  hard-codes a pin again.

## Changed: the Renovate lookup runs in CI

`templates/concourse/renovate-check-pipeline.yml` adds a Concourse job that runs the same
lookup against `develop` on a schedule, so an out-of-date pin shows up on the pipeline rather
than only in someone's terminal. It also tracks `utilities/renovate-report.py`, so a change to
the reporter fails the job that uses it.

## Changed: `setup-orca` updates that take effect

An Orca install could end up running an older build than the `ORCA_VERSION` it claimed. The
task now updates and restarts on each apply when `ORCA_VERSION` is `latest`, and a tag pins it
deterministically. `ORCA_VERSION` exported by Orca's own terminals no longer leaks in and is
silently treated as the machine's preference.

```
/usr/local/bin/orca-pair      # helper: pair a client without reading the pairing code by hand
```

## Changed: `setup-opencode` moves to OpenCode 2.x

Rebuilt against OpenCode 2.x: the server templates, the systemd unit, and the env template all
follow the new layout. The `sync-models` opencode adapter treats *absent* managed fields as
catalog defaults, so a model a user removed from the managed set stops being force-written
back on the next sync.

## Fixed

- **Forgejo** — moves to the 15 LTS line, with Renovate holding it there instead of proposing
  a break against persisted data.
- **fail2ban** — the `jail.local` jail uses `sshd` filter modes; `sshd-ddos` and
  `sshd-aggressive` were removed upstream and broke the jail on a fresh install.
- **Concourse worker** — keeps one name across container recreates, so the worker does not
  register itself repeatedly under new names.
- **Concourse re-runs** — no longer stop at `ssh-keygen`'s interactive overwrite prompt.
- **OpenWebUI re-runs** — the port check no longer trips over the port its own stack is holding.
- **`setup-basics`** — installs `python3-yaml` before reading its `nvm` pin, which a first run
  on a bare box used to hit before the dependency existed.
- **`setup-llm-gateway`** — reads its LiteLLM pin from `versions.yml`; the config guard skips
  placeholder entries instead of rejecting them.
- **Gateway config** — plan fields keep their column, and the compose guard skips comments.
- **`check-versions --json`** — emits valid JSON on every path (previously the report line
  could leak into the document).
- **NetBird** — re-runs refresh the image pins already written into `.env`.
- **`setup-renovate` / Renovate grouping** — `renovate.json` groups the matrix stack, the
  netbird trio and the tensorfold-27b pair, so a bump PR does not arrive as three partial
  ones.
- **`.pytest_cache`** is gitignored — pytest leaves it at the checkout root.

## Upgrade notes

1. `git pull && kwisatz status` — the new entries ship disabled, so nothing runs by itself.
2. A re-run of any task converges and refreshes its image pins from `versions.yml`. Data is
   preserved; expect `docker compose up -d`, not a rebuild.
3. **Before enabling `setup-matrix`**, decide `MATRIX_SERVER_NAME`. It is written into user IDs
   and is immutable once `/srv/matrix/.env` exists; changing it later means a new server.
4. **Before enabling `setup-renovate`**, create a Forgejo bot account and pass its token once:
   `kwisatz apply renovate --env RENOVATE_TOKEN=… --env RENOVATE_GITHUB_COM_TOKEN=…`.
5. **`setup-llm-gateway`** needs `gateway.yml` filled in first (upstreams, addresses, caps) and
   `iptables` access for the `DOCKER-USER` filter.
6. Forgejo users: a 14.x install migrates onto the 15 LTS line. Take a backup of the database
   before re-running the task.
