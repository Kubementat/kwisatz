# v1.0.0

First tagged release. There is no earlier tag, so this release is the **baseline**:
everything kwisatz did before it is recorded only in `git log` (335 commits since
2025-11-12), and `main` is where that record lives.

## What this is

A set of idempotent setup scripts that configure an Ubuntu host (or a docker stack on
one) for LLM workflows and development. `run-setup.sh` reads `machine-config.yml`, runs the
enabled `tasks/setup-*.sh` in order, and every task converges on re-run instead of asking to
be torn down first. 57 task scripts plus `lib/` helpers and `templates/`; data lives in
`/srv/<service>`, `ufw` is the firewall, `traefik` the reverse proxy.

## Work in the window immediately before this tag

- **AMD Strix Halo (gfx1151)**: `setup-strix-halo-tuning` writes the GPU-aperture kernel
  pair, and `setup-gufo-strix-halo-qwen38-{flash,27b}` serve Qwen3.8 through Gufo under
  llama-swap, with `setup-tensorfold-spark-qwen38-*` covering the same models on DGX Spark.
  The fixes in `d7d13c5` are what make those stacks actually start — the pinned Gufo runtime
  ships without an entrypoint, HF snapshot files are relative symlinks into `blobs/`, and the
  container's user is in no group able to open `/dev/kfd`.
- **Hermes** moved out of a docker gateway into its own `virt-runner` VM, wired to the local
  LLM through the custom provider.
- **Conventions**: scripts run as the invoking user with `sudo` for the privileged steps
  rather than requiring a root shell; secrets are resolved from `/srv/<service>/.env` and are
  never substituted into generated files; every `docker compose up -d` has to prove it is
  healthy before the task reports success.

## Versioning

`VERSION` and the annotated tag carry the same `X.Y.Z`, written in the same commit. Semver is
defined by what the user of this repo touches: **MAJOR** = breaking `machine-config.yml` keys,
removed or renamed `tasks/` scripts, or a changed `run-setup.sh` CLI; **MINOR** = a new task
script or a new config option; **PATCH** = fixes to existing scripts. Nothing at runtime reads
`VERSION` (`run-setup.sh` has no `--version` flag) — it is a record, not a switch.

## Requirements

Ubuntu with systemd, `ufw`, docker; `run-setup.sh` needs python3 with PyYAML to read the
config. Non-root sudo-capable accounts run the tasks.

## Known limitations

- `VERSION` is documentation only — there is no `--version` flag to print it, so a stale file
  and a real release can disagree silently. The tag is authoritative.
- The `qwen3.8-27b` llama.cpp catalog entry is the unreliable one on Strix Halo hardware; the
  Gufo and TensorFold entries are the recommended paths there.
- llama-swap rewrites the request's `model` to the served name, so the `model` field in a
  response is not necessarily the id you sent.
